# RAG Evaluation Pipeline Audit - 2026-06-01

## Executive Summary

The observed disconnect was real: `Recall@100` and `HitRate@100` measured whether a relevant document existed somewhere in the top 100, while generation used only a much smaller context slice. A query could score perfectly at retrieval while the LLM never saw the evidence. The evaluator also used a generic QA prompt for SciFact claims, which caused unnecessary abstention.

Primary fixes applied:

- Production retrieval now defaults to `fetch_k=100` and compresses to `retriever_k=8`.
- Hybrid reranking now supports optional cross-encoder reranking.
- Prompt format now uses evidence labels and stricter grounded-answer rules.
- Benchmark evaluation now reports context-level metrics for the passages actually sent to the LLM.
- SciFact generation now uses a claim-verification prompt.
- WinError 10013 failures now surface a diagnostic root-cause hint.

  -> backend/evaluate_rag_benchmarks.py

## Issues Found

### 1. Retrieval@100 Was Treated As Generation Readiness

Evidence:

- `backend/evaluate_rag_benchmarks.py` previously computed only `retrieval_metrics(ranked_ids, qrels[qid], k=args.k)`.
- Generation previously passed only `records[: min(6, len(records))]` to `build_context_from_docs`.

Impact:

- Relevant documents below rank 6 were counted as successful retrieval but omitted from the LLM prompt.
- This explains high `Recall@100` with `"I don't know"` answers.

Severity: Critical

Fix:

- Added `--context-k`.
- Added `context@recall@k`, `context@precision@k`, `context@hit_rate@k`, `context@mrr@k`, `context@ndcg@k`.
- Added `first_relevant_rank`.

### 2. App Default Fetch Depth Was Too Shallow For Reranking

Evidence:

- `backend/rag_chain.py` used `RETRIEVER_K=6`, `FETCH_K=18`.

Impact:

- Reranking had too few candidates to recover buried relevant chunks.
- High chance of missing evidence before generation.

Severity: High

Fix:

- Changed defaults to `RETRIEVER_K=8`, `FETCH_K=100`.

### 3. No Cross-Encoder Reranking Layer

Evidence:

- Existing rerank was dense distance plus lexical BM25-style scoring only.

Impact:

- Semantically relevant but lexically different passages could be misordered.
- Relevant documents could remain buried despite being in top 100.

Severity: High

Fix:

- Added optional `sentence-transformers` CrossEncoder path:
  - `CROSS_ENCODER_ENABLED`
  - `CROSS_ENCODER_MODEL`
  - `CROSS_ENCODER_WEIGHT`
  - `CROSS_ENCODER_MAX_CANDIDATES`

### 4. Prompt Format Was Misaligned With SciFact

Evidence:

- `groq_answer()` used the generic RAG prompt for SciFact claims.

Impact:

- The model treated claims as open-ended medical questions.
- It abstained despite evidence being present.

Severity: High

Fix:

- Added `build_benchmark_prompt()` with SciFact-specific claim verification:
  - `SUPPORTS`
  - `REFUTES`
  - `NOT ENOUGH INFORMATION`

### 5. Prompt Encouraged Abstention Too Easily

Evidence:

- Existing prompt focused on "If evidence is insufficient..." without a positive instruction to answer when evidence exists.

Impact:

- Higher `"I don't know"` rate.

Severity: Medium

Fix:

- Prompt now explicitly says not to abstain when relevant evidence directly supports the answer.
- Prompt cites evidence labels rather than relying only on page labels.

### 6. Generation Metrics Were Not Gold-Answer Metrics

Evidence:

- BEIR/SciFact qrels identify relevant documents, not gold natural-language answers.
- BLEU/ROUGE compared answers to concatenated relevant evidence text.

Impact:

- BLEU/ROUGE are weak proxies here and should not be used as primary quality scores.

Severity: Medium

Fix:

- Report now states this explicitly.
- Added context and faithfulness/relevancy proxy metrics.

### 7. WinError 10013 Was Reported Opaquely

Evidence:

- Groq API failures surfaced raw socket errors.

Impact:

- Hard to distinguish code bugs from OS/firewall/sandbox network denial.

Severity: Medium

Fix:

- Added WinError 10013 diagnostic message in `rag_chain.py`.

## Retrieval Audit

Embedding model:

- Runtime default remains `BAAI/bge-small-en-v1.5`, but benchmark logs show the local environment used `sentence-transformers/all-MiniLM-L6-v2` from environment/cache.
- No dimension mismatch was observed; FAISS loaded and queried successfully.
- Vector normalization is handled by the embedding/vectorstore stack, but FAISS distance semantics are preserved as lower-is-better.

Chunking:

- `RAG_CHUNK_SIZE=800`, `RAG_CHUNK_OVERLAP=120`.
- Metadata retention is mostly sound: filename, source, page label, page key, doc id.
- App expands retrieved chunks to selected page snippets via `source_from_doc_score()`.

Ranking:

- `precision@100 ~= 0.01` is expected on SciFact because many queries have one relevant document and evaluation asks for 100 returned docs.
- The more important measure is now `context_recall@8`, because that indicates whether generation actually receives relevant evidence.

## Generation Audit

Path traced:

```text
FAISS candidate
  -> source_from_doc_score()
  -> rerank_hybrid_records()
  -> build_retrieval_bundle()
  -> build_generation_bundle()
  -> build_context_from_docs()
  -> build_prompt_from_context() or build_benchmark_prompt()
  -> Groq API
```

Root cause of `"I don't know"`:

- Relevant doc may be top-100 but outside the small context.
- Generic QA prompt was wrong for claim-verification datasets.
- Some context snippets omit the precise supporting sentence or require arithmetic.

## Evaluation Audit

Validated:

- `Recall@100`: correct for qrel coverage, but not sufficient for generation.
- `HitRate@100`: correct but too weak.
- `MRR@100`, `nDCG@100`: correct rank-sensitive retrieval metrics.
- `Precision@100`: correct but misleadingly low for sparse qrels.
- BLEU/ROUGE: implemented as lexical overlap against relevant evidence text; proxy only.
- Perplexity: unigram mode is a lightweight proxy; transformer mode is available if the LM is installed.

Added:

- `context@recall@8`
- `context@precision@8`
- `context@hit_rate@8`
- `context@mrr@8`
- `context@ndcg@8`
- `context_precision`
- `context_recall`
- `context_utilization`
- `faithfulness_proxy`
- `answer_relevancy_proxy`
- `abstention_rate`

## Remaining Risks

- Cross-encoder reranking is optional and disabled by default to avoid model download failures in locked-down deployments.
- SciFact is a scientific claim-verification benchmark, not a medical QA benchmark with gold generated answers.
- BLEU/ROUGE/perplexity are secondary proxies; answer faithfulness should eventually use a biomedical NLI or judge model.
- Context compression is extractive; it does not yet perform learned sentence-level compression.

## Future Improvements

- Run full SciFact, NFCorpus, and TREC-COVID once time/network budget allows.
- Enable `CROSS_ENCODER_ENABLED=true` with a locally cached reranker model.
- Add RAGAS/DeepEval integration behind optional extras once dependencies are approved.
- Add query-type routing: claim verification vs direct QA vs summarization.
- Add sentence-level evidence packing so relevant sentences are not diluted by nearby text.
